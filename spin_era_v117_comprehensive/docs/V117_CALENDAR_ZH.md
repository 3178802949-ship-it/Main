# V1.1.7｜截止2028奥运会的有限赛程

新规则的有效时间为2000-01-01至 **2028-07-30（含当日）**。这是本轮明确采用的游戏终点；截止点之后不生成赛历、赛事或新训练阶段。`Area.v117.ensure_date()`会拒绝超出日期，不自动把输入裁回终点。World应在事务提交前验证拟推进日期，避免“新年刷新失败但训练继续使用旧赛历”。

2028年的具体乒乓球比赛窗口采用 **2028-07-16至2028-07-29** 的沙盒安排，完整处于下半月，配合既有World阶段时钟。它不是已核实的官方乒乓球赛日。2028-07-30是本产品选择的奥运会闭幕终点；资料来源未通过独立联网核验，不能据此声称整份官方赛程已重建。

## 参考资料的真实范围

本工程只有2006年的完整示例JSON和按年份生成的通用沙盒结构；2025、2026在原人物库中提供冠军年份／赛事类别锚点，**没有已核实的完整年度赛历**。因此本轮的“参考2025／2026档案”具体指：

- 2027沿用2025的单项世乒赛／世界杯年度类别模式和普通大赛布局。
- 2028沿用2026的团体世乒赛／世界杯类别模式，加入明确模拟的奥运会单打与团体窗口。
- 普通大赛仍按一般配置，不设九站固定名单或数量要求。
- 2028年7月30日后的普通大赛／洲际站不被沿用；模板把亚洲洲际候选安排在6月。此调整同样是模拟安排。

全部未来模板均为`SIMULATED`、`confirmed=False`，逐赛事包含来源与`future_schedule=True`。它们没有冠军、参赛人或官方资格结论。只有用户明确确认本世界的配置后，才可作为模拟赛事运行；团体赛仍需真正的团体阵容适配，不能按单打结算。

## API与兼容

```python
from Area import v117

era = v117.get_era(2028)
calendar = v117.calendar_for_year(2028)
check = v117.validate_calendar(calendar)
day = v117.ensure_date('2028-07-30')
```

新模块复用原资格／年份结构检查代码，使用独立函数上下文扩展2027单项世乒赛、2028团体世乒赛与奥运会、2027—2028世界杯的**规划年份**。它不修改旧Area全局年份集合，也不修改原`data/area_catalog.json`。

`check_entry()`继承原年龄、洲际区域、重复报名及日期冲突逻辑；结果依然只是结构预检，不能取代真实名额、选拔或资格赛。同窗口的奥运单打和团体会被原通用报名冲突规则标记，当前需要World的阵容／多项目赛程适配，不能静默绕过。

`historical_reference`模式把2027／2028模板转换成无日期的`PLANNED`参考；它们仍不成为史实。任何未来赛事缺少明确前瞻声明、试图自证历史已核实，或结束日期越过终点，都会被拒绝。

## 生涯长度的含义

有限终点不是所有开局都保证20年赛季：2024年开局只有约4年游戏时间；2004年开局可覆盖约24年。纯成长数学实验可以研究完整年龄曲线，但不得把越过2028终点的实验年数叙述成已运行的本世界赛历。

本扩展没有自动NPC更新、退役或新生代生成，也没有声称所有2027／2028官方赛事已收录。它解决的是可检查、可截止的前瞻赛程边界。
