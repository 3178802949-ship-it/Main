# V1.1.7 综合版｜叙述证据与多样表达

本模块是规则结算之后的叙述边界，不调用比赛、训练、排名或奖励结算。它把比分、汇总和实际逐板记录整理成中文文本及可逐项核对的事实账本。模板输出可以作为聊天主持的基础；更广泛的文学表达仍由主持生成，不能因此新增事件。

## 公开入口

```python
import narrative_v118 as narrative

report = narrative.render_match(
    log, cards, seed=118, era=era_context,
    as_of_year=2006, as_of_date='2006-02-01', history=previous_history,
)
next_history = report['history']

training = narrative.render_training(receipt)
profile = narrative.preview_profile(card, as_of_year=2006, as_of_date='2006-02-01')
```

`render_match`接受已绑定身份与内容哈希的V1.1.7/V1.1.7 综合版日志。`facts`中的值直接来自输入；每项都带`source_sha256`与JSON证据路径。`sentences`列出每句所依赖的fact ID。`verify_evidence(report, sources)`可用原件逐一复核，不能以摘要替代原件。内容哈希只能检出内容变化，不等同真实作者认证。证据函数核对引用值、类型与文本账本一致性，不自动证明任意自然语言改写的推理正确；主持新增句子仍需核查。

## 不同证据允许的叙述

| 输入 | 可输出 | 不能据此输出 |
| --- | --- | --- |
| 实际聚合比赛 | 获胜者、局数、聚合估计平均板数、动作家族趋势 | 某一分发生的线路、逐板顺序、真实心理误判 |
| 详细逐板全文 | 上述结果，加真实日志中的触球与当时局分，附精确路径 | 未记录的内心、场边私语、冠军史推导出的动作 |
| 由full精简的收据 | 结果与保留的实际汇总 | 全文丢失后的具体逐板重建 |
| 精简收据及匹配的外置全文 | 核对全文哈希、世界、比赛、参与者、种子、规则、胜者及局数后，可引用全文 | 另一场比赛的全文或只凭相同姓名混配 |
| 训练回执 | 实际CA、PA、疲劳和技术变化记录 | 凭叙述另给能力、突破、冠军或积分 |

轻量人读文本明确写“聚合估计”及“聚合抽样”，不只依靠后台标签作区分。详细摘录仅从实际非发球触球取样，未接到球不写成已完成技术。日志即使被重新签内容哈希，也必须满足11分制/两分差的合法终局以及完整BO3/BO5/BO7的停赛规则。

## 风格、人格与时代

风格偏好和人物线索经`Card.v118.narrative_view`提供在`profile_guidance`，标为`NARRATOR_ONLY`。它们不成为比赛事实，也不作为获胜、失误或训练收益的因果说明。模拟默认性格词不代表真实私下人格；公开表达也不能被升级为心理诊断。没有资料就保留无资料状态，不补造采访或私下对话。

`as_of_date`按日过滤材料。`Area.v118.context_for_date`的嵌套时代对象可直接传入；模块识别其`as_of`，并把同一天传给人物线索过滤。明确日期与年份冲突会拒绝；晚于观察日期或不属于该年的时代上下文会被扣留。时代主题在文本中写作“本世界采用的时代主题”，不冒称完整真实赛季的已核实事实。

两张不同ID的卡若同名，显示名会附加A/B和球员ID，以免胜者、比分及逐板摘录的身份含混。

## 多样性与连续性

结果句有8种句式；事实内容随真实比分、动作汇总及详细日志取样变化。同一seed和同一输入得到同一输出。传入`history`可避免最近3种结果句式连续重复，只保存最近12项模板记录，调用不修改原history。

这不是已认证的无限文学多样性。它没有调用远程语言模型，也不伪装生成有采访依据的场边故事。`fictional_atmosphere`只提供可选创作边界，默认正文为空；主持可以另写明确标注为虚构的场馆氛围，并保持其与`facts`分离。
