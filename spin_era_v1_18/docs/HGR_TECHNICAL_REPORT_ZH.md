## 3. 几何、胶皮与削球解释

### 几何与战术

`Game/geometry.py`使用统一的归一化绝对坐标：x单位为半台宽0.7625米，y单位为半台长1.37米；端0在负y面向正y，端1相反。站位和触球点可以位于台后，不局限于台面。正反手由当前端别、持拍手和身体位置派生；`receiver_table_side`与`receiver_contact_side`分别记录名义台面侧和相对身体的实际接触侧。

台面中路与追身分别判断，长球弹跳点与削球手台后拦截点分开。几何输出包括米制横向/前后距离、方向、直斜线、大角度、反向移动、侧身、跨步和恢复压力。整合引擎将距离、恢复、移动惯性与负荷纳入实际到位需求，线路选择也使用对手可见站位和已观察弱侧。

左右手对位不是固定压制关系。例如异手组合的正手斜线可能对到对手反手，但对手的防守、反撕、到位和直线反制仍参与结果。未知持拍手保持unknown并明确报告，不猜成右手或左手。

在双方居中、从名义正手位击球的简化场景下，同手组合正手斜线对正手、异手组合正手斜线对反手；直线对应关系相反。真实接球侧仍以当前身体位置和拦截点重新计算，不能把这张关系表当作永久压制加成。

缺少手别时，FH/BH无法无歧义转换为绝对侧；纯几何返回unknown/None。整合层仍记录抽样的物理落点和移动，并把旧相对标签标为未解析兼容回退。这一分支不等于已经准确模拟了未知人物的真实左右手线路。

### 双面胶皮与接触

规范字段为`card['rubbers'] = {'fh': ..., 'bh': ...}`，手别仍使用独立的`hand/handedness`，握拍不由任一字段代替。支持inverted、short_pips、raw_pips、long_pips、anti_spin及unknown。兼容card/equipment中的双面rubber映射与显式单面别名，冲突拒绝；一个全人共用的scalar胶皮标签拒绝。防弧须显式声明`experimental_anti_spin=True`，输出继续标记experimental，不能说成已有充分史料认证。

新增30个稳定动作标识，含正/反、专业/普通削球和胶皮接触变体；这不等于新增30项能力。动作合法条件包括：

| 动作 | 允许情境 |
| --- | --- |
| 短颗粒/生胶弹击、快拨、撞击 | 非下旋长/半长球，不能处于bad到位 |
| 颗粒突击下旋 | 长/半长下旋，不能处于bad到位 |
| 颗粒快挡／台内挑击 | 前者对长/半长上旋；后者对短/半长球且非bad |
| 长胶拱／磕挡／刮 | 拱对下旋或不转且非bad；磕挡对长/半长上旋；刮对短/半长或侧旋 |
| 长胶削 | 非下旋长球，仍需后续到位、质量和失误结算 |
| 长胶低摩擦反攻 | good到位、长/半长球；不转质量≤124，或上旋/侧上旋质量≤112 |
| 普通/专业削球 | 长球；长胶与防弧不允许借此常规削下旋 |

长胶/防弧不能执行常规高摩擦弧圈、拧拉或反拉。合法只代表可以尝试，不能跳过球员技术、到位、旋转识别或失误判定。缺失胶皮保留unknown，不追加设备专用动作，旧接触出球透传。

出球转换只负责旋转、强度、速度、弧线与变化信息，不给质量、G或必胜奖励。长胶接触结果随来球旋转/强度及击球方式变化；反转不是恒定高质量。对手能够通过观察与适应影响后续处理。

主要接触近似可审计：短颗粒/生胶主动攻击旋转分别取已算base_strength的0.44/0.32，速度分别增加7/9；长胶被动接触按拱0.52、刮0.54、其他被动接触0.72保留并反转来球有符号旋转，主动削球结合来球上旋0.64和原生成旋转0.28；长胶低摩擦反攻只取原生成旋转0.16。防弧以0.80反转来球旋转、速度减13，属于实验。转换强度上限170、速度范围45—190。

这些是显式实验接触参数，不是材料物理拟合。读球适应使用实际出球variation及累计曝光影响错误概率；没有独立“本板确定误判”事件骰，因此报告只能统计识别风险概率项，不能把一次综合失误归因为已经证实的心理误读。

### 专业削球循环

专业与普通削球分开，正/反手各按既有技术结构使用防守42%、旋转27%、落点23%、连续8%。没有“所有专业削手反手必强、正手必弱”的身份惩罚或隐藏倍率。到位、质量与错误仍为条件随机结果；球员可失去有效触球、触球失败、普通回球或优秀回球。

深台准备以实际站位表达；左右与长短调动产生移动和恢复成本，不能再叠加原固定角色到位奖励。进攻方需要根据实际削球旋转和质量选择稳定拉削、冲吊、调动或提高风险；削球方在弱质量上旋、对手空当或还原不足时可尝试反攻。高质量削球本身不直接登记自动得分。

候选逐板层将good/limited/bad继续带入既有质量和错误结构，miss表示未能有效触球。对同一到位等级仍有质量噪声、旋转、技术和稳定性的不同条件，不能把等级直接当成固定胜负。削球没有直接winner抽签；得分需由对手后续处理失败、未到位，或削球手自己的进攻路径产生。

局间自检、form repair、read bonus、20/60/20心理检定及实时反制阶段阈值保留原公式。对手知识来源改变：至少两侧各有3次观察后才比较可见质量/失误估计弱侧；策略分类至少6次观察。原侦察公式中的对手read项使用明确的中性估计120，不读取真实当日G。这个未校准估计及观测门槛可能改变战术节奏，需要与胜率分开验收。

## 4. 存档、日志与训练兼容

旧日志仍按原内容验SHA，不能新增字段后重hash假装原件。旧世界加载先验证原格式和SHA，缺少新规则字段时继续旧引擎；保存保持原格式，不向旧payload补写默认手别或胶皮。新格式已经由封存原world.py的实际loader验证拒绝，防止按旧规则静默续跑。

新增逐板元数据复用`technique_path`，补充动作分类、实际击球侧、胶皮、几何和移动信息；旧action/quality/reach/return_state及比赛身份仍供既有消费者读取。新动作映射到已有43子项，解析时必须与注册表一致；不允许任意technique_path注入训练。专业/普通的正反削球主路径分别为fh.defense、bh.defense；四个子项共同参与质量，不意味着一板同时领取四份成长曝光。旧规则的chop仍按原table.chop_control映射，封存日志不回改。

Training公共入口、连续XP、许可和复盘窗口公式保持原规则。赛后曝光继续要求每专项至少8次，并从合格专项选择最多3个复盘目标；一次比赛日志不等于直接获得能力奖励。

启用接口示例（cards必须是完整合法卡，装备假设由调用者显式声明）：

不传新规则参数时保留旧行为；上面两种调用是独立示例，不会自动把独立match写进world。世界内比赛仍通过WorldSession写入与保存。当前HGR候选只支持BO7。

### 6.3 攻削得分路径与移动

“严格削中反攻”定义为同一分内该选手已经完成过至少一次自身削球，再出现主动进攻尝试；不直接把所有削球手进攻都计入。拉削失误指前一板是对手削球、随后进攻直接失败，不能据此认定每次都是旋转误判。

| 新规则对抗 | Joo严格削中反攻FH／BH | 其中直接得分FH／BH | 对手拉削直接失误 | 对手接削后直接进攻得分 | 平均单次拦截移动 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 施拉格2003／朱世赫2003实验 | 692／0 | 13／0 | 450 | 48 | 0.743米 |
| 许昕2013情境（2012基线）／朱世赫实验 | 570／20 | 7／0 | 355 | 29 | 0.744米 |

新规则全部四组的直接削球winner均为0。削球可令对手在下一板失误/不到位；削球手主动反攻可沿普通进攻路径得分。旧代码第三板战术额外winner概率未限定offensive，会令少量被动chop也被登记直接winner；新候选仅对真正进攻动作开放该额外判定，修补了这个分支。

施拉格组新日志实际记录patient_loop 2,728次、spin_pace_mix 1,987次、wide_movement 1,596次、short_long 640次以及observed_weak_side 2,014次。这些策略参与候选权重与物理目标选择，不是比赛结束后追加的叙述。整组到位负荷最大6.10；长回合与恢复移动会累积负担。旧日志无米制移动与该负荷字段，报告保留UNAVAILABLE，不称其负荷等于0。

## 7. 未解决问题与平衡风险

- 当前为规则候选与条件模型，不是逐毫秒物理飞行或胶皮材料实验模型；坐标、节奏和接触参数仍需独立实战资料校准。
- 原型库缺少手别、握拍和装备资料。实验假设不能升级为史实，unknown行为需要持续检查，不能借默认值掩盖缺失。
- 2013许昕年度输入缺失、朱世赫存储聚合不一致，限制历史解释范围；不能凭本次胜率确认现实人物强弱。
- 到位、长胶旋转转换和观察学习同时影响攻削循环；施拉格组胜场变化16场、Ma/Fan变化7场，说明普通对抗也受影响。下一步应以同一卡和未参与开发的留出种子，分别开关几何、胶皮、观察与角色准备站位，测各自效应，不能凭整体结果给单一机制下结论。
- 两组攻削平均回合和长回合比例下降，可能与移动负荷、接触合法性及节奏选择共同有关；不能未经对照就认定更真实。长胶反手削后反攻在一组0次、另一组20次，仍需检验弱球阈值和使用机会，不能只证明函数能调用。
- 历史级生涯潜力兑现、真实完整赛历、人口稀有率和NPC自动职业演进仍属于既有未验收范围，不因本技术补丁通过而自动完成。
