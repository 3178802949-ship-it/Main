# 《旋球年代》V1.1.6 整合候选｜AI端结算与叙述交接

本文件用于新聊天窗口加载本次总包。**先读取根目录开幕文档、版本和验收记录，再使用本文件；不要仅凭本文件叙述模拟结果。** 本包是可执行规则与候选数据，尚不等于完成现实校准、全NPC赛历或正式1.0。

## 1. 先确认正在加载什么

1. 解压到独立目录，运行`python verify_package.py`核对发行清单与SHA256，再运行`python self_test.py`。不要把多个版本源码混合覆盖，也不要删除`runtime/`中看似旧版、实际被新接口依赖的文件。
2. 需要完整发行复验时，在工程根目录运行`python tests/run_release_qa.py`，阅读本次生成的`checks/release_qa/RELEASE_QA.json`及退出状态、检查数量和失败项。`reports/RELEASE_QA.json`是冻结的发行证据；默认复验不覆盖它，以免改变随包文件后导致清单校验失败。不能把旧报告当成刚刚运行的结果。没有代码执行能力时，明确说“尚未执行”，不得声称验收通过。
3. 确认世界模式、起始日期、模型年龄、球员身份、时代和排名球员池。不存在的参数不要凭人物姓名推断成已确认史实。
4. 读取完整角色卡与`data/`中的来源标记。保留43子项、P6、PA估值、独立潜能、学习天赋、偏好、疲劳、伤病、XP、许可和排名分账，不能只抄CA。
5. 运行Area赛历检查，列出示例日期、资格或洲际地区问题；让用户知道哪些是可执行的沙盒设定，哪些还不是已核实的真实赛历。用户已决定不另设“九大赛”固定名单或必达站数，按一般大赛处理。
6. 有新版本世界存档时，加载整个世界检查点，确认规则版本与事件账本，再推进。不要把旧试玩存档的“两项子技术”计划静默解释成本版“两项技术大类”。

## 2. 模块边界与唯一写入路径

| 模块 | 负责的事情 | AI不得替代的结算 |
| --- | --- | --- |
| Game | 逐板对抗、选招、到位、回球质量、局间/局内调整、比分与动作证据 | 根据人物名气或目标剧情指定赢家，再编造击球过程 |
| Card | 43子项与P6重算G9/CA，完整角色导出，成人/青年Elo与赛事S-PTS账本 | 直接给CA加点、把PA当比赛加成、把样本名次称作世界排名 |
| Training | 每月两个顺序阶段、大类特训、子项专精、一般训练与卓越、疲劳和成长兑换 | 补掷有利骰、免费增加训练次数、忽略XP/许可/软帽或体力代价 |
| Area | 时代主题、预设卡来源、赛事与资格检查、赛历覆盖和未确认项 | 自动把历史冠军写入新世界线，或把现代赛制无条件套回旧时代 |

**整合世界的状态写入只通过`world.py`中公开的`WorldSession`接口进行。** 模块接口用于计算、验证与独立检查；不要在同一世界中一边调用权威接口，一边手工修改内部状态或另行调用旧`runtime`成长函数。一个结果只能结算一次。

整合接口的职责如下，调用前仍须检查本版实际函数签名：

| `WorldSession`接口 | 使用时机 |
| --- | --- |
| `create(...)` | 以明确角色、日期、世界ID、模式、球员池和赛历创建新世界 |
| `card(player_id)` | 读取结算后的完整生涯卡；不靠手抄G9或CA更新状态 |
| `train_phase(...)` | 执行一个当月阶段，按需引用本世界已执行的复盘比赛ID |
| `play_practice(...)` | 执行训练对抗；不将其当作正式赛事结果 |
| `run_event(...)` | 执行已检查的赛事完整单败签表，而非先指定冠军再补结果 |
| `confirm_sandbox_event(...)` | 确认某项示例赛事在本沙盒内执行，不将其认证成真实历史 |
| `set_calendar(...)` | 显式切换当前年份赛历或调整未结算事项，保留旧赛历归档 |
| `rankings(...)` | 按当前日期读取排名分账与完整池声明 |
| `consistency_check()` | 检查世界时钟、人物与账本的一致性 |
| `dump()` / `load(...)` | 保存和恢复整个世界；不能用一张展示卡代替 |

低层函数、测试辅助函数和源码里的实验入口不等于玩家可无限调用的奖励接口。不要绕过世界账本直接追加训练、排名积分、冠军窗口或恢复体力。

## 3. 一次有效动作的固定流程

执行顺序为：

**读取当前检查点 → 验证身份、时钟、阶段与资格 → 提交唯一事件ID和玩家选择 → 程序结算 → 检查返回收据 → 保存新检查点 → 根据证据叙述。**

- 事件ID必须稳定且唯一。同一动作因网络或聊天重试时，不得换ID领取第二次奖励。训练和练习不能占用赛历预留赛事ID；更新赛历时，也不能将已用训练或比赛ID改作赛事ID。
- 当前月份与阶段由存档决定，不能由叙述任意跳转。第二阶段不能先于第一阶段；完成第二阶段后才进入下月。
- 主角阶段驱动世界时钟。其他球员可以补结算到该阶段，不能先消耗未来阶段；练习双方及正式赛全部参赛者都必须与主角的月份和阶段一致，不能只比较月份，也不能拿静态旧状态直接参赛。
- 本版赛事必须完整落在当前半月窗口：第一阶段为1—15日，第二阶段为16日至月末。比赛证据同时保存双方与世界的阶段；训练复盘只接收本世界当前月、且不晚于该球员当前阶段的比赛。不能在上半月先执行下半月赛事，再把未来的复盘信息用于上半月训练；跨半月赛事需要显式日程适配，不能绕过检查。
- 发生验证错误时，状态不应部分落地。应解释具体缺项或冲突，修正输入后再提交，不得“先按大概结果继续”。
- 保存和恢复需包含规则版本、世界身份、时钟、人物状态、资格、比赛/训练/赛事结果ID、排名账本和仍在有效期内的窗口。不能只保存一张展示卡。
- 本轮没有执行的事情只可标为计划、提案或推断。不得通过“略过一个月”偷算训练、比赛、恢复或积分。

## 4. Training计划必须按大类解释

健康月份允许两次阶段结算。每个训练阶段选择：

- 两个不同的技术大类，例如`read`与`bh`，不是直接把两个子值当成两个大类。
- 一个体能大类，例如`stamina`。
- 对任一已选技术大类，可另选两个不同且归属于该类的子值进行专精。例如在`bh`中选择`defense`与`placement`。专精替换原本分散的子项选择，使用相同的专项骰预算，并增加疲劳消耗。

未选的七个技术大类各有受控的一般训练机会，其他五项体能也有低剂量一般训练。**一般训练保留卓越机会，但卓越不等于无条件提升2—4级。** 读取真实骰和当前等级：低等级可能获得受软帽限制的直接小提升，高等级主要取得XP或既有突破许可，仍需按原成本兑换。

健康训练阶段的骰预算必须按本版读取，不能沿用旧试玩“每个选中子项各两骰”的结构：

| 项目 | 每阶段 | 两阶段健康月 |
| --- | ---: | ---: |
| 特训技术 | 每大类两个不同子项各一骰，共4骰 | 8骰 |
| 特训体能 | 所选体能2骰 | 4骰 |
| 一般技术 | 其他7大类各一个子项1骰 | 14骰 |
| 一般体能 | 其他5体能各1骰、低剂量 | 10骰 |

专精固定各大类的两个合法子项，替代按权重选中的两个子项，不增加骰数。一般技术原始D100≤3记为卓越：低于120时可有受软帽限制的+1；120—127主要取得额外XP；128以上可取得一个既有许可，但仍需XP及软帽余量。不得把每个大类的一般训练擅自扩展为该类全部子项满量训练。

高质量教练的一般课纠错通道与上述卓越分开：非卓越的一般技术条目，只有当前等级至少128、尚低于软帽、XP已达半级成本时，才可能取得一个既有许可；概率随环境质量增加但不超过0.33，基准club为0。同一条一般训练最多取得一个许可，不能把卓越和纠错重复叠加。所有环境的一般D100≤3卓越机会仍保留，不能误认为低质量环境完全没有突破机会。

阶段结束后核对疲劳消耗与恢复。高疲劳会降低有效训练效率；休整会消费一个阶段。康复状态可能限制可训练阶段，不能用专精或冠军窗口绕过。不可凭“天才”“国家队”“冠军”字样免除代价。

本版候选疲劳成本为训练阶段基础15、每个专精大类另加3；恢复按环境计算。疲劳结余按未截断的总负荷减恢复后再限制到0—100，不能利用峰值封顶消掉超量负荷。休整不暂停月份生理变化，年龄损耗或自然成熟仍可能发生。

每次收据至少核对：大类和子项、原始与校正骰、次级骰（若有）、XP到账与余额、许可发放与余额、旧值和新值、软帽、疲劳前后、阶段ID和月序号。若CA整数未动，仍应展示已发生的子项进步和XP积累。

## 5. Game与赛事排名不能混成一步

比赛参与者必须从当前世界卡读取，逐一确认人物身份、年份/年龄及疲劳。不要把同一真人的两个年度快照当作同世界的两个独立NPC，除非用户明确选择跨时代展览模式。

执行Game后，先检查比分结构和比赛参与者，再从逐板日志读取动作、到位、回球质量、实际失误和局间判断。随后由世界接口登记比赛与需要的排名变化。训练对抗不自动成为正式冠军或官方排名赛。

正式赛入口执行的是所提供参赛池的单败签表。若只有2、4等少量参赛者，明确报告签表规模和沙盒性质；不能把小型模拟夺冠等同现实世界大赛强度。练习与正式赛均要求人物的月份和半月阶段与世界时钟相同，先通过阶段结算同步NPC，不能让未同步的静态参照卡免费跳过衰退与训练。

单场Elo与整站赛事S-PTS分开结算：

- 成人和青年Elo是两套账本；团体盘次不能未经规则许可挤入成人单打账本。
- S-PTS依赛事级别和整站最终成绩记一次，不是每赢一场都领取一次冠军积分。
- 排名按指定日期处理365天窗口及最佳站数；过期积分不能长期累加。
- 没有在同一时点加载完整且合格的球员池，只可报告Elo、S-PTS和样本内名次，不得称为“世界第几”。370张跨年预设快照不是370名同期选手。当前示例世界`complete_roster=False`，传入`rankings(complete_pool=True)`会被拒绝；参数本身不能认证完整球员池，更不能手工改标记绕过。

旧击球引擎有临时回调替换；需要并行时使用本版Game公开的进程隔离路径，不得自行在线程中同时运行低层比赛函数。进程隔离不等于旧引擎已完成全部线程安全重构。

## 6. Area检查与历史资料的使用

Area的时代主题是技术环境与传播候选，不会因为主角夺冠自动提升全体NPC。自动NPC逐月发展和完整技术扩散尚未由主题文档本身实现。

跨年时，人物与排名账本继续保留，但新年赛历需要显式调用`set_calendar(...)`切换。`consistency_check()`可能返回`valid=True`且`calendar_refresh_required=True`：这表示12月末结算已经有效完成，新年赛历仍待加载，不是应重掷或撤销该阶段的错误。继续推进前先检查并切换新年赛历。旧赛历进入归档，同年已完成赛事不能重写或删除。不能把“已经到下一年”叙述成下一年的真实赛历已经全部加载。

检查三大赛时，应检查具体年份与项目：奥运延期年份、世乒赛单打/团体、个人世界杯空缺年份不可混用。大型洲际赛还需地区与资格核对。其他大赛按一般赛事层级处理，不要求每年恰好九站；示例场站和日期不能宣称为已核实的历史完整赛历。

预设卡里的历史冠军锚点为原资料参照，不代表当前模拟世界已经发生的冠军。自由生涯的冠军和成长机会只能来自本世界实际结算。若用户选择历史剧情复现，应先声明哪些节点为外部锚定，不能再用锚定结果证明通用比赛模型预测准确。

本版`historical_reference`世界是只读参照，并不是已经完成的历史剧情播放系统。需要开始实际训练或比赛时，创建明确标记的`sandbox`分支；不要绕过只读检查改写历史资料。沙盒赛事也需调用`confirm_sandbox_event(...)`明确确认其模拟身份后，才交给`run_event(...)`执行。

年度快照不是自动升级补丁。自由生涯推进到下一年时，不能用该人物后来一年的预设卡覆盖已保存人物；那会跳过真实训练和衰退，并重置独立天赋、XP与许可。已进入世界的人物继续使用其状态账本。加载新NPC或进行明确声明的历史重建时，才按来源规则选取快照。

开局也不能无提示地借用旧年度年龄。使用更早快照作新世界起点时，需显式标记`PRIOR_BASELINE_NOT_GROWN`并提供`model_start_age`；它表示采用旧能力基线，不表示中间年份已经训练和老化。未来年份或未来快照日期不能提前加载，同一真人的多个快照不能作为同期独立人物。

原资料包含“现实男性原型”及“女性替代世界线”等分层元数据。不得把男性原型成绩称为真实女性历史成绩，也不得在新聊天中悄悄改变世界性别设定。数值推断、结构优化与现实史料必须保持不同来源标签。

## 7. 叙述合同

- 可以叙述程序实际记录的动作、落点、到位、判断、成长和代价。
- 可以把心理与战术意图写成有条件的解释，但不得说没有记录的旋转、线路、伤情或临场调整“实际发生过”。
- 不得根据胜负倒推一段不存在的名场面；不得为了让冠军更像史实而重掷比赛。
- 当日志只提供聚合信息时，叙述保持相同粒度。缺逐板日志时，不编逐板纪实。
- 区分角色感知与玩家/系统可见数值。高认知改善的是判断与选择，不直接变成力量、全部技术或必胜。
- 不把一场比分改善当作训练因果证明；不同比赛种子会产生不同结果。

## 8. 每次结束与跨聊天恢复

向玩家给出本次选择、实际结果、关键骰或结算摘要、专项/体能/XP/许可/疲劳变化、排名变化、未完成或未确认事项。结算失败与未执行项单独说明。

保存完整世界检查点，并明确当前日期、月序号、已消费阶段、下一步可选动作和存档路径。新聊天必须重新读检查点及相同规则版本，不从上一段自然语言猜测状态。较旧版本的存档需要经过显式迁移或保持旧规则，不能静默混用。

旧V116的608条职业校准、此前试玩的60项测试，只验证它们各自版本。新训练的普通卓越、专精疲劳、大类选择及新世界账本需看本次发行的验收记录。对于历史级潜力、人口稀有率和真实年龄曲线，继续使用“候选/未完成校准”的措辞。
