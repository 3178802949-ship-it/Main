# 《旋球年代》V1.1.6 整合候选｜玩家与人工交接指南

本包把比赛、角色与排名、训练、时代与赛程拆成Game、Card、Training、Area四个模块，再通过整合世界接口共同结算。完整模拟请优先使用总包；分包适合单独检查或交接模块，依赖和自检以各包清单为准。

## 1. 第一次启动

解压总包到独立目录，先读根目录README与开幕文档。核心运行使用Python标准库；按README核对文件校验后，在工程根目录运行：

```bash
python verify_package.py
python self_test.py
python tests/run_release_qa.py
```

新运行的完整复验写入`checks/release_qa/RELEASE_QA.json`。`reports/RELEASE_QA.json`保留发行时冻结证据，避免每次检查改写清单内文件。

只检查某个独立分包时，按其清单运行`python self_test.py --module Game`，或将模块名换成`Card`、`Training`、`Area`。完整世界与开幕流程使用总包。

然后使用包内启动示例创建新世界或恢复检查点。把总包、开幕文档和已有世界检查点交给新AI窗口。需要代码执行能力的结算，必须由实际运行程序完成；只读文件的AI可以解释规则和准备选择，但不能假装已经掷骰、改变能力或赢得赛事。

创建一个干净开局并输出完整卡和检查点：

```bash
python examples/start.py --output examples/my_new_world
```

另外运行一次四人沙盒淘汰赛及两阶段训练的完整示例：

```bash
python examples/start.py --demo --output examples/my_demo
```

选择尚不存在或为空的输出目录，保护已有存档。包内`examples/demo_output/START_WORLD.json`是干净开局，`DEMO_WORLD.json`是已发生示例结果的检查点；新生涯不自动继承示例赛事的冠军和积分。

开局应明确：世界模式与年代、起始日期、人物卡和模型年龄、培养条件、采用的赛历及尚未确认项目。历史剧情与自由生涯可以使用同一批参考资料，但外部锁定的历史节点和实际模拟结果需分开标记。

本版的`historical_reference`仅用于只读参照；可玩的训练和比赛使用`sandbox`分支。它尚未提供自动按史实播放冠军节点的剧情模式。示例赛事需要先确认作为本世界的模拟赛事，确认不等于认证了真实历史赛历。

## 2. 四个模块各做什么

| 模块 | 玩家能看到的内容 |
| --- | --- |
| Game | 比赛比分、具体技术动作、到位与回球质量、战术判断和调整 |
| Card | 43技术子项、G9、P6、CA、PA估值、成长余量、学习特点、疲劳伤病、XP许可、排名账本 |
| Training | 两次月度阶段选择、两个技术大类和一项体能特训、可选子项专精、一般训练、卓越机会与体力代价 |
| Area | 七段时代主题、预设卡来源、赛事/资格/赛历检查、三大赛、一般大赛和洲际赛事覆盖 |

完整卡中的CA是当前技术与身体的聚合结果，PA是可调整的潜力估值。高PA不保证未来达到同样CA，也不能直接提升击球。每项学习天赋和身体发展条件独立存在。

预设卡本轮优化主要使它们具备一致的结算结构、独立发展档案和明确来源。未经证据校准的旧属性不做全员升降，因此“可运行、可训练”不等于“每个现实球员的能力已被准确认证”。原始卡保留作对照。

旧年度快照不能直接当成当前年龄的新卡。若明确采用较早的能力基线，需要同时标明“尚未补算中间成长”并给出模型起始年龄；人物进入世界后持续推进同一存档，不按年份自动替换后来更强的预设卡。

## 3. 一个月怎样训练

健康月份有两次顺序结算。每次选择两个不同的技术大类和一个体能方向。例如：

| 阶段 | 技术大类一 | 技术大类二 | 体能 |
| --- | --- | --- | --- |
| 第一阶段 | 战术阅读`read` | 反手`bh` | 灵活`agility` |
| 第二阶段 | 接发`receive` | 正手`fh` | 耐力`stamina` |

选大类时，系统按预算分配相关子项训练。想进一步定向，可以在已选大类中指定两个合法子项，例如反手防守与反手落点；它们替代原本分散的子项选择，增加疲劳，不额外赠送更多专项骰。

每个健康阶段执行4次技术特训骰、2次所选体能骰，另有7次一般技术骰与5次低剂量一般体能骰。大类专精改变这4次技术骰的目标，不把它们再翻倍；这是本版与之前试玩的一个规则区别。

未选大类仍有一般训练。一般训练也可能出现卓越，但高水平提升仍受XP、突破许可和身体软上限约束。不要把一次卓越理解成“所有技术普涨”或世界级专项无条件增加数点。

优质教练还可以在满足等级、XP积累与软帽条件的一般课中提供纠错许可，与原始D100≤3的卓越机会分别记录，同一条训练不会重复领两次许可。因此，普通环境仍可能出现卓越，优质环境则更擅长把已有积累变成有效突破。

高强度专精会积累疲劳，影响后续训练效率和比赛状态。休整会占用阶段，康复状态也可能减少可训练阶段。安排需要在补短板、强化优势、兑现复盘机会与恢复之间取舍。

每次结束应看到技术、身体、XP余额、许可、疲劳和实际执行阶段。CA没有变化也可能已有进步：子项增长可能被聚合取整遮住，或XP尚未积累到下一级。

## 4. 比赛与排名

训练对抗用于观察和练习，不自动生成正式冠军或排名积分。正式比赛先核对赛事、参赛身份和资格，再运行对抗与结算。

本版以半月为最小训练阶段：先由主角推进，再将其他参赛者补结算到相同月份和阶段；练习也遵守这一要求，不能直接使用未同步的静态NPC。正式赛必须完整处于当前1—15日或16日至月末窗口；跨半月赛事需要额外的日程适配。不能让NPC预先训练未来阶段，也不能提前参加月底赛事后再回头领取月初训练收益。复盘证据保留比赛时双方及世界的阶段，未来阶段的比赛不能影响过去训练。

Elo反映对抗评分；S-PTS反映整站成绩，两者分开。成人、青年和团体结果也不能混为同一个账本。S-PTS按规则过期并选取最佳站数，不能把每个胜场都当作一次冠军积分。

只有完整同年代、合格的参赛池才能声明世界名次。角色库里的跨年快照不能直接相加成为世界人口；同一个人的不同年度卡也不能作为多个同期NPC重复排名。示例世界明确不具备完整池，要求完整排名的调用会被拒绝，不能靠打开一个参数将样本名次变成世界排名。

## 5. 时代与赛历为什么有“待确认”

Area会检查赛事年份、单打/团体项目、重复ID、日期和报名冲突，并检查洲际资格。资料不足时保留提示，不能用叙述把缺失信息补成史实。

按用户的最新决定，不另设九大赛固定名单或必达站数，其他大赛一般处理。带`SIMULATED`或未确认标签的名字、日期、场站是沙盒设定；不能称为2006或其他年份的真实完整赛历。三大赛也不是每个年份三项都举办，需要分别检查。

跨年后需要明确切换新年赛历；旧赛历会归档，已经完成的同年赛事不可改写。12月末结算可正常完成，同时返回`calendar_refresh_required=True`提醒；继续前先加载新年赛历，不重掷已经完成的阶段。人物状态、冠军与排名账本不会因此清空。赛历中的赛事ID为预留身份，不能被训练或练习占用；新赛历也不能占用已经发生的其他动作ID。

人物卡和时代资料可能同时记录现实男性原型、女性替代故事设定及合成能力评估。开局确认采用哪个世界，不把故事成绩冒充真实女子历史，也不随意改写原始资料。

## 6. 怎样交给下一位AI

同时提供：

1. 相同版本总包与根目录开幕文档。
2. 完整世界检查点，而非只有一张展示卡或上一段故事。
3. 尚未确认的赛历、资格或世界设定。
4. 你希望下一次做的动作：下一阶段训练、报名赛事、比赛、休整或查看状态。

让AI先读`AI_HANDOFF_ZH.md`，按当前阶段继续。已有事件不能重复结算，失败操作不能先写一半；没有执行函数时不能声称能力或排名已经改变。

## 7. 当前适合怎样使用

本版适合检验训练选择、对抗因果、卡片成长、排名分账、时代/赛程检查和跨聊天保存的一致性。历史级197—198潜力的充分兑现、人口稀有率、真实年龄曲线、自动NPC职业赛历和经济系统仍需后续校准或开发。

新增规则改变了长期训练预算和疲劳取舍，不能把旧608条职业结果当作新规则已完成长期平衡的证据。本次测试结果以本版生成的验收记录为准，未运行、失败或尚未实现的项目需如实保留。
